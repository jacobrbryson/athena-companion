ATHENA / LOCAL SERVER

Give Athena a home on your network.

Your computer can host her API, local models, memories and a browsable offline Wikipedia library. You choose the server and approve its setup.

Owner-operated preview. The connection flow and service configuration are available. Installation still requires a compatible database export, HTTPS and Google sign-in configuration. This is not yet a one-click or fully offline installation.

Download the local server setup kit

1. Prepare your server

Use a trusted Athena source checkout on the computer you choose. Extract the kit into deploy/local inside that checkout, then follow its README. It includes configuration, not the application source or your private data.

Install Docker with Compose, select models your hardware can run, and choose how much disk space to reserve for Wikipedia and memories. The kit starts with CPU inference; GPU setup depends on the host.

2. Keep ownership with you

Supply an HTTPS hostname and trusted certificate. Configure Google sign-in for that address. Use fresh local secrets and a restricted database account for Athena; keep database administration and deployment credentials outside her runtime.

3. Bring your memories

The current migrations require legacy tables, so a reviewed schema and consent-scoped memory export are needed first. The README explains the missing baseline, access grants, media files, encryption and backups. Cloud and local memories do not synchronize in this preview.

4. Download models and Wikipedia

Run the model download commands in the README when you are ready. Choose your Wikipedia language and edition at Kiwix and place the ZIM file in the kit's Wikipedia folder. The library is browsable locally; automatic use of those articles in Athena's replies is planned.

5. Start and connect

After completing the prerequisites, validate the configuration and start the services using the README commands. Sign in at your local HTTPS address and verify chat, Brain status and persistent memories.

In the web client, open Menu → Local server, enter that address, approve it and save. On subsequent visits the web client checks that address and opens its local companion before sign-in. Credentials stay with each installation.

If discovery is blocked, open the local address directly. Browsers may require local network permission.

Choose what can leave home

Cloud server fallback is off until you enable it. Frontier models on your local core are a separate choice: configuring a provider key enables the existing guarded fallback. Voice and tool calls currently depend on frontier providers. Google login and default avatar assets still need internet.
